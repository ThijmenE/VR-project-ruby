## Wat ging goed

    We hebben in het project met de scrum methode gewerkt, waar we alles in 3 sprints hebben opgedeeld maar 4 weken hadden ingepland voor het project, dus als we uitloop hadden was het geen probleem. We hebben voor de sprints het project opgedeeld in drie delen: Week 1, minigames. Week 2, Kamer en playtest. Week 3, Robot builder en het praten van de robot. We hadden nog wel een beetje uitloop waardoor we in de 4e week nog models hebben toegevoegd en dingen hebben genoteerd voor ons portfolio examen.
    
    Het samenwerken ging erg goed tijdens het project, we zitten naast elkaar te werken, dus we weten van elkaar waar diegene mee bezig is en of alles goed gaat. We hebben alles goed in de github genoteerd en hebben goed gecommuniceerd. We zijn onze afspraken die we hebben gemaakt nagekomen. We hebben beide goed door gewerkt waardoor we het optijd hebben afgekregen. Ook hebben wij voor elke feature een branch aangemaakt waardoor alles goed overzichtelijk was.

## Wat kan beter

De branches kan bij ons nog wat beter. Wij hebben elke branch 1 keer gebruikt en dat naar een grotere branch gemerged, waardoor we op een gegeven moment alleen nog maar dingen gingen updaten in de grote branch en niet meer in de kleinere lossere branches. Dit zorgde voor onoverzichtelijkheid en merge conflicts, dus dat moeten we voortaan anders aanpakken.

Soms kan de concentratie bij ons nog wat beter, We hebben een paar keer gehad dat we het laatste uurtje niet zo goed meer kunnen concentreren, waardoor we niks meer afkregen en elkaar gingen afleiden.

feedback voor thijmen: Robot builder had anders gemaakt kunnen worden zodat animaties wel mogelijk waren voor de robot.

## Voortgang van taken

De game hebben we helemaal klaar gekregen en het eindresultaat is precies hoe wij het wouden. We hebben in de github een planning gemaakt waar alle taken instaan en alle tijden voor elke taak. Het praten van de robot heeft bij mij de meeste tijd gekost, omdat het veel code was en code moest combineren. We hebben als je de robot bouwt dat de robot dan een random persoonlijkheid krijgt (Blij, enthousiast, zielig, bang). De robot praat elke 15 seconden een zin van de persoonlijkheid, als je iets goed doet in een minigame reageert de robot er positief op. Het heeft voor mij best wel wat tijd gekost, ook omdat ik nog nooit iets heb gedaan met dialogue, dus dat was allemaal nieuw voor mij.

## Verbetervoorstellen

Samenwerking: Om te zorgen dat we aan het einde van de dag niet meer zo snel afgeleid raken en productief blijven, gaan we in het volgende project van 4 weken onze taken slimmer inplannen. Elke ochtend tijdens de stand-up verdelen we het werk zo dat we het lastige codeerwerk voor 14:00 uur doen, en de kleinere, simpelere taken (zoals kleine bugfixes, dingen opruimen of documentatie) bewaren voor na 14:00 uur. Dit willen wij op het github bijhouden, zodat we aan het einde van de dag nog wel productief bezig kunnen.

Eigen ontwikkeling: ik wil in het volgende project dat ik ga maken de code netter opbouwen en meer overzichtelijk schrijven, zodat mijn teamgenoten sneller begrijpen wat er in mijn code staat. Ik wil in het vervolg mijn code laten reviewen door een teamgenoot op leesbaarheid zodat ik weet of mijn code logisch is geschreven. Na dat de code is gereviewd zou ik het pas pushen naar de branch waarin ik werk.
